# Codex 上下文洞察 · 安装使用说明

作者：凪梦尘

---

## 这份东西是什么

一个小工具，给你的 Codex 装上一块"仪表盘"。

Codex 干活的时候会烧 token、占上下文、花掉钱、耗掉时间。这些它自己都记着，但没人替你看。这个工具把这些数字整理成一张网页报告，你双击就能看。

**一句话：它能告诉你，你花的钱和时间都去哪了。**

---

## 你会看到什么

打开报告，从上往下是这样几块：

### 最上面一排数字

| 看到的东西 | 意思 |
|---|---|
| 会话数 / 轮次 | 你一共开了几个 Codex 对话，来回问了多少次 |
| **计费 Token** | 这次一共用了多少 token。输入比输出多得多是正常的,因为每一轮都要把整个对话重新发一遍 |
| **预估成本** | 大概花了多少钱。**这是估算,不是账单**,以 OpenAI 官方账单为准 |
| **缓存命中** | 有多少内容命中了缓存。这个数越高越省钱,因为缓存的部分便宜得多 |
| 推理 Token | 模型"想"了多少,不是"说"了多少 |
| 工具调用 | Agent 调用了多少次工具(读文件、改代码、跑命令…) |
| **平均每轮** | 每次来回平均花多久 |

### Token 构成（两个圆环）

- **左边那个环**:看全部 token 花在哪——没缓存的输入、缓存命中的输入、模型说出来的、模型想过的
- **右边那个环**:只看模型自己产出的部分——**写出来多少 vs 想出来多少**

为什么要分两个环?因为输入通常占 99% 以上,如果只有一个环,输出那一小块小到看不见,你就没法判断"模型是不是光在思考不干活"。

### 上下文压力（一根彩色条）

每个会话离它的上下文上限还有多远,分四档:

- 绿色 (<50%):很宽松,继续用
- 浅绿 (50–70%):正常
- 黄色 (70–90%):开始注意了
- **红色 (≥90%):下次提问很可能触发自动压缩**,上下文会被裁剪,模型可能"忘事"

看到红色的会话,建议开个新对话,或者让它先把要点总结下来。

### 上下文趋势（一条折线）

沿着时间看,这个会话的上下文是怎么一点点涨上去的。

- 线往上爬 = 对话在变长
- **线突然掉下来 = 发生了自动压缩**(上下文被裁掉了)
- 右上角会写"窗口 400.0K · 峰值仅占 10.0%"这种,告诉你离上限还有多远

### 耗时统计（这是重点）

这块回答"时间到底花在哪了"。

**一根双色横条**:

- 蓝色 = **模型在工作**(思考、生成、传输)
- 绿色 = **工具在执行**(跑命令、读文件、改代码)

下面四个数字:

| 数字 | 意思 |
|---|---|
| 轮次总耗时 | 所有对话来回加起来用了多久 |
| 工具总耗时 | 其中有多少时间是在等工具跑完 |
| **平均每轮** | 每次来回平均多久 |
| 平均每工具 | 单次工具调用平均多久 |

**怎么看这张卡**:

- 如果**绿色占大头** → 时间都耗在工具上了。可能是命令太慢、文件太大、或者它在反复读同一批东西
- 如果**蓝色占大头** → 时间耗在模型生成上。这通常是正常的,但如果是简单任务却很久,可能是上下文太长了(模型要读的东西太多)
- 右下角还会列出**最慢的几个轮次**,点开对应会话就能看当时在干什么

### 按日用量（柱状图）

最近 14 天每天用了多少 token。柱子突然变高的那天,回去看看是不是跑了个大任务。

### 模型分布 / 工具调用 / 对话解剖

- **模型分布**:哪个模型在干活,各占多少
- **工具调用**:shell、apply_patch 这些工具各被调了多少次
- **对话解剖**:你说的话、模型说的话、它思考的次数、工具调用次数、工具结果数——**只数个数,不看内容**

### 会话明细（表格）

一行一个会话,能看到:模型、工作目录、轮次、请求次数、token、成本、峰值/窗口、压缩次数、当前占用率。

想找"哪个会话最贵"、"哪个会话快撑爆了",看这张表。

## 怎么装（三步）

### 前提

电脑上要有 **Python 3.9 或更高版本**。

检查方法:打开终端(Windows 是 PowerShell),输入:

```
python3 --version
```

看到 `Python 3.9.x` 或更高就行。没有的话去 python.org 下载安装。

> Windows 上如果 `python3` 不认,试试 `python --version` 或 `py --version`。

### 第一步:下载

有 Git 的话:

```
git clone https://github.com/AronRolstonAlex/codex-context.git
cd codex-context
```

没有 Git:打开 https://github.com/AronRolstonAlex/codex-context ,点绿色的 **Code** 按钮 → **Download ZIP**,解压,然后进入那个文件夹。

### 第二步:安装

在那个文件夹里执行:

```
python3 install.py
```

它会做两件事:

1. 把插件复制到 `~/.codex/plugins/codex-context-insight/`
2. 在 `~/.agents/plugins/marketplace.json` 里登记一个叫「本机插件」的市场

想先看看它会动哪些文件、不实际写入:

```
python3 install.py --dry-run
```

### 第三步:在 Codex 里启用

1. **完全退出 Codex,再重新打开**(不是关窗口,要真正退出进程)
2. 打开 **Plugin Directory**(插件目录)
3. 找到 **「本机插件」** 这个市场
4. 安装 **codex-context-insight**
5. 第一次跑到钩子时,Codex 会问你要不要信任——**审阅后点允许**

> 第 5 步很重要。Codex 默认不信任任何插件自带的钩子,这是它的安全设计,不是出错了。不允许的话,插件不会自动更新报告。

## 怎么用

### 平时:什么都不用做

装好之后,你正常用 Codex 就行。插件会在这些时机自动刷新报告:

- 会话开始时
- 每一轮结束时
- 上下文压缩前后
- 会话结束时

**最多每 2 分钟刷新一次**,不会一直占着 CPU。

### 想立刻看:手动跑一条命令

```
python3 ~/.codex/plugins/codex-context-insight/scripts/report.py --out ~/我的报告.html
```

然后用浏览器打开那个 html 文件。

Windows 上路径是 `%USERPROFILE%\.codex\plugins\...`。

### 只要数字,不要文件

```
python3 ~/.codex/plugins/codex-context-insight/scripts/report.py
```

终端里直接打印摘要,不生成文件。

### 直接问 Codex

装好之后可以直接跟 Codex 说:

> 看一下我最近的 token 用量和成本

它会调用插件里的技能帮你生成。

### 常用的几个参数

| 想干什么 | 加这个 |
|---|---|
| 看更多历史会话 | `--limit 100`(默认只算最近 30 个) |
| 看全部 | `--limit 0` |
| 指定输出位置 | `--out D:/报告.html` |
| 同时导出数据 | `--json 数据.json` |
| Codex 装在别处 | `--codex-home D:/我的codex目录` |

## 它保证了什么

### 只读元数据

它读的是:**token 数、模型名、工具名、时间戳、条目个数**。

它**不读**:

- 你输入的提示词内容
- 模型回答的内容
- 工具调用的参数
- 工具的输出结果

这不是一个开关,是写死在代码里的——解析器根本不会去取那些字段。项目里还有专门的测试:往提示词和参数里塞假的密钥文本,断言它们进不了任何数据结构。

### 不联网

纯本地 Python,没有任何第三方依赖,不发任何网络请求。报告是一张自包含的网页文件,断网也能看。

### 数据不离开你的电脑

报告文件就在你自己电脑上。除非你主动分享,没人看得到。

## 出问题了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报告说「没有找到会话」 | 这台机器还没跑过 Codex,或者 Codex 数据不在默认位置 | 确认用过 Codex;不在默认位置就加 `--codex-home` |
| 成本那一栏全是 `—` | 你用的模型不在内置价格表里 | 这是**故意的**,不猜数字。想加就在 `scripts/context_core.py` 里补一行 |
| 数字比预想的少 | 默认只看最近 30 个会话 | 加 `--limit 0` |
| 钩子不生效、报告不自动更新 | 插件钩子没被信任 | 在 Codex 里审阅并信任;或直接手动跑命令 |
| 装完在 Plugin Directory 里找不到 | 没完全重启 Codex | 真正退出进程再开 |
| 报告底部说「有未识别的行类型」 | Codex 更新了会话文件格式 | 不影响统计,已安全跳过。可以反馈给作者 |
| 中文显示成方块 | 系统缺中文字体 | 装个 Noto Sans CJK 之类的字体 |

## 它做不到什么(说清楚,不糊弄你)

有几样东西 dsh-context 有,但这个插件**做不了**,因为 Codex 压根没记这些数:

1. **系统提示词 / 工具定义 / 注入上下文的分别占比**
   Codex 只记"一共多少输入",不拆成这几类。所以那个六色堆叠条做不出来。

2. **首 token 时间(第一个字多久蹦出来)**
   Codex 记的是每个事件完成的时刻,看不到流式输出的第一包。

3. **完整的命令行文本**
   插件只记"调用了 shell 几次",不记具体命令。这是隐私决定,不是能力不足。

## 想改它

| 想改什么 | 改哪里 |
|---|---|
| 加模型价格 | `scripts/context_core.py` 里的 `PRICE_TABLE` |
| 改默认上下文窗口 | 同文件的 `DEFAULT_CONTEXT_WINDOWS` |
| 改报告外观 | `scripts/report.py` 里的 `CSS` |
| 改自动刷新频率 | `hooks/session_report.py` 里的 `REBUILD_INTERVAL_SECONDS` |
| 加新的统计项 | `scripts/context_core.py` 里加字段 → `scripts/report.py` 里加卡片 |

改完要重新装一次(`python3 install.py`),因为装在 `~/.codex/plugins/` 下的是副本。

## 卸载

```
cd codex-context
python3 install.py --uninstall
```

它会删掉插件目录和 marketplace 里的登记。

**不会自动删的**:已经生成的报告文件、Codex 里的钩子信任记录。这两样要你自己手动清。
